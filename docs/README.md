# Оглавление разбора

> [!TIP]
> Если читать один раздел — [§5. Приёмка](1-install/05-acceptance.md): там весь результат в одной таблице. Если два — добавьте [§9. Чего E2E не защищает](2-crypto/09-limits.md): именно этого обычно нет в инструкциях про шифрование.

Разбор состоит из пяти частей. Первая — установка, остальные — механика, цифры и эксплуатация.

---

## Часть 1. Установка

- **[§1. Pi: система и диск](1-install/01-pi.md)** — Raspberry Pi OS, разметка NVMe, ext4 без резерва под root, монтирование по UUID с `nofail`, отдельный пользователь-хранитель.
- **[§2. Доступ только по ключу](1-install/02-ssh.md)** — отдельная пара ed25519 на клиенте, `authorized_keys` вне досягаемости пользователя, `Match User` в `sshd_config.d`, `chroot` + `internal-sftp`, проверка `sshd -T`.
- **[§3. Windows: rclone и диск](1-install/03-windows.md)** — WinFsp, отпечаток хоста, два раздела `rclone.conf` (транспорт и crypt), команда монтирования с разбором каждого рычага.
- **[§4. Автозапуск, который переживает выключенную Pi](1-install/04-autostart.md)** — задание планировщика с правильными настройками, обёртка с повторами, почему разовый запуск — плохая идея.
- **[§5. Приёмка](1-install/05-acceptance.md)** — одиннадцать проверок, включая учения по восстановлению и видимость диска из программ, запущенных от администратора.

## Часть 2. Шифрование

- **[§6. Три слоя](2-crypto/06-layers.md)** — что делает транспорт, что шифрование, что WinFsp; кто что видит на каждом участке пути.
- **[§7. Формат файла](2-crypto/07-format.md)** — `RCLONE\0\0`, nonce, блоки по 64 КиБ, арифметика накладных расходов, имена в base32768 и предел длины имени.
- **[§8. Проверка руками](2-crypto/08-proof.md)** — записать файл на `X:` и убедиться, что на Pi нет ни имени, ни содержимого; что этот опыт доказывает и чего не доказывает.
- **[§9. Чего E2E не защищает](2-crypto/09-limits.md)** — метаданные, усечение и откат, кэш с открытыми файлами, журнал с открытыми именами, `rclone.conf` как ключ.

## Часть 3. Скорость

- **[§10. Замеры](3-perf/10-measured.md)** — диск, канал, сквозной результат, мелкие файлы; методика и команды, которыми числа сняты.
- **[§11. Где узкое место](3-perf/11-bottlenecks.md)** — почему криптография бесплатна, откуда берутся 65 МБ/с на запись, арифметика мелких файлов, что действительно ускоряет.

## Часть 4. Эксплуатация

- **[§12. Повседневная работа](4-ops/12-daily.md)** — что копировать напрямую, что через диск, как проверять доехавшее и как не терять данные на ровном месте.
- **[§13. Отказы и диагностика](4-ops/13-failures.md)** — таблица «симптом → причина → что делать», включая срыв автозапуска и предел длины имени.
- **[§14. Риски и восстановление](4-ops/14-recovery.md)** — потеря паролей, смерть SSD, потеря ключа, кража Pi, чтение вынутого диска на другой машине.

## Часть 5. Надёжность

- **[§15. Периметр](5-hardening/15-perimeter.md)** — `nftables` по умолчанию наружу закрыт, отключение входа по паролю для основного пользователя без шанса запереть себя снаружи.
- **[§16. Наблюдение](5-hardening/16-monitoring.md)** — SMART, свободное место, «жив ли диск», ротация журнала; systemd-таймер, который это делает сам.
- **[§17. Бэкап шифротекста](5-hardening/17-backup.md)** — копия без ключей, расписание, проверка восстановления. Самая дешёвая страховка в этой схеме.
- **[§18. Чего нет вовсе](5-hardening/18-gaps.md)** — LUKS, версии и корзина, доступ снаружи, многопользовательский режим, ротация ключей.
