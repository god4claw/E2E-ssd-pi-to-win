# §7. Формат файла: что именно лежит на Pi

<sub>[Главная](../../README.md) · [Часть 2](README.md) · [← §6](06-layers.md) · [§8. Проверка руками →](08-proof.md)</sub>

Pi хранит не файлы, а контейнеры `rclone crypt`. Формат открытый и простой, поэтому его видно побайтово — и полезно понимать, что именно вы увидите, если заглянуть на диск.

## Раскладка

| смещение | размер | что это |
|---|---|---|
| 0 | 8 байт | метка формата `RCLONE\0\0` |
| 8 | 24 байта | nonce (случайное число, с которого начинается счёт блоков) |
| 32 | 65 552 байта | первый блок: 64 КиБ открытого текста + 16 байт тега Poly1305 |
| … | … | остальные блоки того же вида |

Nonce увеличивается на единицу для каждого следующего блока. Поэтому блоки нельзя переставить местами или вырезать из середины незаметно, а вот обрезать файл по границе блока — можно ([§9](09-limits.md)).

Имя файла шифруется отдельно, тем же примитивом, и кодируется в `base32768` — иероглифы в листинге это не «китайская локаль», а зашифрованное имя.

## Накладные расходы

```
overhead = 32 + 16 × ⌈size / 65536⌉
```

| исходный файл | на диске | overhead |
|---|---|---|
| 62 Б | 110 Б | 48 Б |
| 64 КиБ | 65 584 Б | 48 Б |
| 1 МиБ | 1 048 864 Б | 288 Б |
| 1 ГиБ | 1 073 741 824 + 262 176 Б | ≈ 0.024 % |
| 10 ГиБ | + 2 621 472 Б | ≈ 0.024 % |

То есть «ровно 48 байт» — только для файлов до 64 КиБ. Дальше добавляется по 16 байт на каждые 64 КиБ, и на больших файлах это доли процента, которыми можно пренебречь при планировании места.

## Имена

- Шифрование имени **детерминированное** — иначе сервер не смог бы найти файл по имени без индекса. Следствие: одинаковые имена дают одинаковый шифротекст, видно совпадение имён, но не сами имена.
- `base32768` кодирует 15 бит в одном символе, а символ в UTF-8 занимает 3 байта. Итог: имя на диске примерно в **1.6 раза длиннее** исходного (плюс 16 байт на тег), но заметно короче, чем в base32.

Предел длины имени компонента в ext4 — **255 байт**, а не символов. Отсюда предел для открытого имени:

```
255 / 1.6 − 16 ≈ 143 байта
```

| исходное имя | на диске | результат |
|---|---|---|
| `отчёт-2026.pdf` (24 Б) | ≈ 64 Б | нормально |
| 100 символов латиницы (100 Б) | ≈ 186 Б | нормально |
| 200 символов (200 Б) | ≈ 348 Б | **не скопируется** |
| глубокий путь с длинными компонентами | — | Windows может упереться в `MAX_PATH` (260 символов) |

Именно поэтому «сохранённая веб-страница целиком» — плохой кандидат для `X:`: там длинные имена и глубокая вложенность. Обход простой: такие папки пакуются в архив до копирования.

> [!NOTE]
> Ошибка при превышении выглядит невнятно — в журнале может появиться `SSH_FX_BAD_MESSAGE` или `SSH_FX_FAILURE`. Если видите её на конкретном файле — первым делом проверьте длину имени, а не сеть.

## Что видно в листинге

```
/娦従銿芛䘞蚠魽叡㲿/芪璤疝禉䈉費⏌㔠⺿    110 Б    12 окт 14:03
```

Читается так: каталог и файл — зашифрованные имена; размер соответствует исходному плюс накладные расходы; время изменения — настоящее. Больше ничего: ни типа файла, ни исходного имени, ни содержимого.
