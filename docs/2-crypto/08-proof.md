# §8. Проверка руками

<sub>[Главная](../../README.md) · [Часть 2](README.md) · [← §7](07-format.md) · [§9. Чего E2E не защищает →](09-limits.md)</sub>

Не верьте на слово — проверьте сами. Опыт занимает пять минут и не требует доверия ни к документации, ни к автору.

## Записать

На Windows, на смонтированный диск:

```powershell
mkdir X:\_proof
"СЕКРЕТНАЯ-СТРОКА-ДЛЯ-ПРОВЕРКИ-12345" | Out-File -Encoding utf8 X:\_proof\plain.txt
```

Подождите несколько секунд: запись отложенная (`--vfs-write-back 5s`), файл уезжает не мгновенно.

## Посмотреть на Pi

```bash
f=$(sudo find /srv/cloud/data -newermt "-5 minutes" -type f | head -1)
echo "$f"                          # путь: иероглифы вместо имени
sudo stat -c%s "$f"                # размер: 110 байт вместо 62
sudo head -c 40 "$f" | od -c       # начало: RCLONE\0\0 и nonce
sudo grep -ac "СЕКРЕТНАЯ" "$f"     # 0 — открытого текста нет
sudo grep -rac "СЕКРЕТНАЯ" /srv/cloud/data   # 0 — и во всём хранилище тоже
```

Результат настоящего прогона:

```
путь:   /srv/cloud/data/娦従銿芛䘞蚠魽叡㲿/芪璤疝禉䈉費⏌㔠⺿
размер: 110 байт   (исходных данных было 62 байта)
0000000   R   C   L   O   N   E  \0  \0 230 372   { 351 027   &   E   N
0000020   K   0   ) 200 271   8   = 033   b 224   _   & 230   ! 035   x
поиск открытого текста: 0 совпадений
```

## Как это читать

| наблюдение | что означает |
|---|---|
| имя каталога и файла — иероглифы | имя зашифровано и записано в `base32768` ([§7](07-format.md)) |
| первые 8 байт — `RCLONE\0\0`, дальше 24 байта | метка формата и nonce; Pi знает только «это файл rclone» |
| 62 → 110 байт | 32 байта заголовка + 16 байт тега Poly1305: файл короче 64 КиБ |
| `grep` по открытому тексту даёт 0 | содержимое действительно зашифровано |
| `grep -rac` по всему хранилищу даёт 0 | это не единичный случай: шифрование работает во всём дереве |

## Чего этот опыт не доказывает

- **Что на клиенте нет открытых копий.** Кэш на `C:`, журналы, временные файлы приложений — всё это вне канала и вне Pi ([§9](09-limits.md)).
- **Что файл целостен как целое.** Poly1305 закрывает каждый блок: он не даст незаметно подменить байты внутри блока, но не заметит, если файл обрезать по границе блока.
- **Что имена не утекают косвенно.** Совпадающие имена дают совпадающий шифротекст; структура дерева и размеры видны.
- **Что восстановление возможно.** Для этого нужен отдельный опыт — [§17](../5-hardening/17-backup.md).
