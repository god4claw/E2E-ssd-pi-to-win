# §13. Отказы и диагностика

<sub>[Главная](../../README.md) · [Часть 4](README.md) · [← §12](12-daily.md) · [§14. Риски и восстановление →](14-recovery.md)</sub>

Таблица собрана из реальных отказов этой установки и из того, что обычно ломается в таких схемах.

| симптом | причина | что делать |
|---|---|---|
| Вход на Pi отбивается сразу после аутентификации | `/srv/cloud` принадлежит не root или доступен на запись группе | `sudo chown root:root /srv/cloud && sudo chmod 755 /srv/cloud` ([§1](../1-install/01-pi.md)) |
| `ssh` под `cloud` даёт приглашение | правило `Match` не подхватилось | `sudo sshd -T -C user=cloud`, проверить `Include` в `sshd_config` ([§2](../1-install/02-ssh.md)) |
| `couldn't connect SSH: dial tcp … connectex` при входе в систему | Pi выключена или не успела подняться | обёртка с ожиданием ([§4](../1-install/04-autostart.md)); разовое задание здесь не спасает |
| Диск исчез через несколько дней без причины | у задания планировщика лимит выполнения 3 суток | `-ExecutionTimeLimit ([TimeSpan]::Zero)` ([§4](../1-install/04-autostart.md)) |
| `SSH_FX_BAD_MESSAGE` / `SSH_FX_FAILURE` на конкретном файле | имя после шифрования длиннее 255 байт | укоротить имя или упаковать папку в архив ([§7](../2-crypto/07-format.md)) |
| rclone спотыкается на контрольных суммах | забыты `shell_type = none` / `md5sum_command = none` | дописать в раздел `pi` ([§3](../1-install/03-windows.md)) |
| Диск монтируется, но пуст | `remote` указывает не на `pi:/data` либо не тот пароль | сверить раздел `secret`, **не пересоздавая** его вслепую |
| Скорость ≈ 11 МБ/с | линк согласовался на 100 Мбит/с | `ethtool eth0 \| grep Speed`, кабель, порт роутера |
| Скорость ≈ 40 МБ/с и скачет | работа через Wi-Fi | витая пара |
| Диск «завис», проводник не отвечает | rclone ждёт сеть, запросы копятся | `Stop-Process -Name rclone`, затем перезапуск обёртки |
| Кэш занял весь `C:` | не заданы `--vfs-cache-max-size` / `--vfs-cache-min-free-space` | задать, перезапустить ([§3](../1-install/03-windows.md)) |
| Файл есть на `X:`, но ещё не на Pi | отложенная запись: файл ждёт закрытия и паузы | подождать 5–10 с, посмотреть журнал |
| Приложения от администратора не видят `X:` | буква создана обычным процессом | проверить в приёмке, при необходимости `--network-mode` ([§3](../1-install/03-windows.md)) |
| Задание «выполняется», а диска нет | обёртка крутится, но rclone падает повторно | `mount.log`: обычно ключ, отпечаток или пароль |
| Диск виден, объём нулевой/огромный | `rclone about` не поддержан, включён `--vfs-disk-space-total-size` | убрать флаг либо задать реальный объём |

## Как смотреть журнал

```powershell
Get-Content $env:LOCALAPPDATA\rclone\mount.log -Tail 50 -Wait
```

Что искать:

- `Failed to create file system` — конфигурация, ключ, отпечаток;
- `couldn't connect SSH` — сеть или выключенная Pi;
- `corrupted on transfer` — испорченный блок (Poly1305), редкий случай;
- `vfs cache: failed to upload` — сеть отвалилась во время отправки; повтор после восстановления.

## Что смотреть на Pi

```bash
journalctl -u ssh -n 50 --no-pager      # попытки входа и отказы chroot
sudo sshd -T -C user=cloud              # действующие правила
df -h /srv/cloud                        # место
findmnt -n /srv/cloud                   # смонтирован ли диск
```
