# §12. Повседневная работа

<sub>[Главная](../../README.md) · [Часть 4](README.md) · [§13. Отказы →](13-failures.md)</sub>

Правила простые и все следуют из замеров и устройства слоёв, а не из привычки.

## Что копировать напрямую

Крупные файлы — **не** через букву диска, а через `rclone copy`/`copyto`: так нет пятисекундной паузы write-back и двойной записи в кэш.

```powershell
rclone copyto D:\video.mp4 secret:video/video.mp4 --stats-one-line
rclone copy D:\photos\2026 secret:photos/2026 --transfers 8 --checkers 8
```

Через `X:` удобно работать, а не заливать: открыть, посмотреть, поправить, сохранить. Для «положить 200 ГБ» — только `rclone`.

## Что копировать через диск

- Мелкие правки в файлах, документы, картинки — то, что вы открываете и сохраняете руками.
- Всё, где важна «обычная» работа программы: редактор, архиватор, просмотрщик.
- Файлы, которые вы не хотите держать на `C:` — но помните: то, что вы читали, лежит в кэше открытым ([§9](../2-crypto/09-limits.md)).

## Много мелких файлов

Не распаковывайте архивы прямо на `X:`: ≈ 200 файлов/с при 64 КБ — это 12.8 МБ/с. Распакуйте локально и скопируйте папку целиком:

```powershell
rclone copy D:\unpacked secret:project --transfers 8
```

## Как проверить, что всё доехало

```powershell
rclone check D:\photos\2026 secret:photos/2026 --size-only
```

`--size-only` здесь не выбор, а необходимость: в конфигурации `disable_hashcheck = true` и `md5sum_command = none`, потому что у пользователя нет оболочки. Контрольных сумм на той стороне взять негде, и rclone сравнивает только размеры.

> [!WARNING]
> `rclone check --size-only` проверяет **наличие**, а не целостность. Файл того же размера с испорченным содержимым он пропустит. Единственное, что ловит порчу, — расшифровка при чтении (Poly1305 откажет на испорченном блоке). Для настоящей проверки нужна копия и периодическое чтение ([§16](../5-hardening/16-monitoring.md)).

## Что на `X:` лучше не держать

| тип | почему |
|---|---|
| Базы данных (SQLite, 1С, серверные БД) | нет блокировок и атомарного переименования: повреждение почти гарантировано |
| Почтовые архивы (PST/OST) | файл правится кусками и постоянно открыт; кэш будет расти, синхронизация — рваться |
| Образы виртуальных машин | постоянные случайные записи и большой объём; через SFTP это не работает |
| Git-репозитории с активной работой | тысячи мелких файлов и частая перезапись: каждый коммит — это шторм обменов |
| Файлы, которые правят одновременно два процесса | блокировок нет, последний записавший выигрывает |

## Привычки

- **Смотреть журнал**, когда что-то странно: `Get-Content $env:LOCALAPPDATA\rclone\mount.log -Tail 30 -Wait`. Уровень `NOTICE` не пишет имена, но показывает ошибки.
- **Отмонтировать** — завершить процесс: `Stop-Process -Name rclone`. Незавершённая отправка из кэша продолжится при следующем монтировании.
- **Проверять место** — `rclone about secret:` или свойства диска, а не «на глаз».
- **Не выключать** Windows «на кнопку» с открытыми файлами на `X:`: недописанный файл останется в кэше и уедет при следующем старте, но с потерей последних секунд.
