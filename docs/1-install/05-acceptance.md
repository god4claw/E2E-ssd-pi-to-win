# §5. Приёмка

<sub>[Главная](../../README.md) · [Часть 1](README.md) · [← §4](04-autostart.md) · [§6. Три слоя →](../2-crypto/06-layers.md)</sub>

Установка принята, когда пройдены все одиннадцать пунктов. Не десять, не «всё работает, кроме одного» — каждый пункт закрывает отказ, который иначе всплывёт через недели.

| № | что проверяется | как | ожидание |
|---|---|---|---|
| 1 | диск смонтирован по UUID и переживает перезагрузку | `findmnt -n /srv/cloud`, затем `reboot` | строка с `ext4`, `noatime`; после перезагрузки — снова |
| 2 | права на запирание корректны | `stat -c '%U:%G %a' /srv/cloud /srv/cloud/data` | `root:root 755` и `cloud:cloud 700` |
| 3 | правило SSH применено | `sudo sshd -T -C user=cloud` | есть `chrootdirectory /srv/cloud` и `forcecommand internal-sftp -d /data` |
| 4 | оболочка недоступна | `ssh -i <ключ> cloud@<IP> 'id'` | приглашения нет, команда не выполняется |
| 5 | хранилище отвечает | `rclone lsd secret:` | код выхода 0 |
| 6 | диск виден и показывает верный объём | `Test-Path X:\`; свойства диска против `rclone about secret:` | совпадает |
| 7 | шифрование настоящее | проба из [§8](../2-crypto/08-proof.md) | все четыре условия |
| 8 | автозапуск зарегистрирован и переживает выключенную Pi | `Get-ScheduledTask RcloneCloudMount`; затем перезагрузка Windows при выключенной Pi | состояние `Ready`, лимит выполнения снят, диск появляется после включения Pi |
| 9 | скорость в рамках ожидаемого | `rclone copyto` 1 ГБ | ≥ 80 МБ/с на гигабитной сети |
| 10 | данные восстанавливаются по бумажке | собрать отдельный remote из записанных паролей и прочитать файл — [§17](../5-hardening/17-backup.md) | файл читается |
| 11 | диск виден из программы, запущенной от администратора | `Test-Path X:\` в консоли «от имени администратора» | `True` — либо зафиксировано обратное и включён `--network-mode` |

Пункт 9 — не придирка: результат заметно ниже 80 МБ/с означает, что соединение ушло на Wi-Fi, порт согласовался на 100 Мбит/с или кабель плохой. Диагностика — `ethtool eth0 | grep Speed` на Pi и [§11](../3-perf/11-bottlenecks.md).

Пункт 10 — единственная проверка, которая подтверждает не «система работает», а «систему можно починить». Пока она не пройдена, пароли на бумаге — это предположение, а не факт.

## Чего этот гейт не доказывает

Приёмка подтверждает, что схема собрана и данные ходят шифротекстом. Она **не** доказывает, что:

- на клиенте нет открытых копий: кэш `%LOCALAPPDATA%\rclone\vfs`, журналы, временные файлы приложений — [§9](../2-crypto/09-limits.md);
- данные выживут при смерти SSD — копия делается отдельно, [§17](../5-hardening/17-backup.md);
- Pi закрыта снаружи — периметр настраивается отдельно, [§15](../5-hardening/15-perimeter.md);
- диск не «зависнет» после обрыва сети — обёртка из [§4](04-autostart.md) поднимает процесс, но не чинит сеть;
- шифротекст целостен как файл целиком: Poly1305 защищает блоки, а не файл от усечения — [§9](../2-crypto/09-limits.md).
